# 产品演化评估 · 2026-07-07

> 一次产品经理视角的现状评估与演化建议快照,基于 v0.2.0 时点的代码现状。

## 背景

Markdown Nice(Tauri v2 + Vue 3 本地 Markdown 编辑器)发展至 v0.2.0,核心能力:编辑(CodeMirror)、预览(markdown-it)、editor/split/preview 三视图、文件与文件夹管理、主题(默认浅色)、自动更新。本文对该节点做一次 PM 视角的盘点与规划。

## 现状速评

### 1. 预览的代码高亮是假的(硬伤)
`useMarkdown.ts` 里的 `hljs` 是 stub——`highlight()` 只做了 `escapeHtml`,无语法着色;`PreviewPanel.vue` 另 new 了一个没配 highlight 回调的 markdown-it。结果:预览代码块单色无高亮。对一个 Markdown 编辑器是观感硬伤。

### 2. 渲染逻辑重复且分裂
`useMarkdown` 与 `PreviewPanel` 各持一个 markdown-it 实例,配置不一致,`useMarkdown` 疑似闲置死代码。应统一为单一渲染管线。

### 3. 定位张力(最该先想清楚)
- 名字「Markdown Nice」(致敬 mdnice 排版)+ `preview_max_width`、`--strong-color` 等排版变量 → 暗示「主题排版 + 输出」
- welcome 文案「A quiet place to read and write Markdown」+ 现状功能 → 现状是「安静写作工具」(类 iA Writer / Typora)

两方向功能优先级几乎相反,需先定方向再排期。

## 战略选择

| 方向 | 核心 | 主战场 |
|---|---|---|
| A. 安静写作工具 | 编辑体验、专注、本地知识管理 | Typora / iA Writer / Obsidian |
| B. 排版输出工具 | 多主题、复制富文本、导出 | mdnice Web 版,卖点在本地+隐私 |

**推荐:A 为主,B 做轻量输出层。** 写作工具的留存靠日常打开;排版输出低频但高光。本地写作后顺手给「复制为公众号格式 / 导出」即可覆盖 B 的 80% 价值,不必做主题市场这类重运营的事。

## 路线图(按 ROI 分层)

### P0 — 基础体验(立即,几天内)
- 真·代码高亮(接 highlight.js 真包,统一渲染实例)— 修硬伤
- 最近文件列表(现在每次都要 Cmd+O 重新找,留不住人)
- 大纲导航(按 heading 自动生成,长文必备)

### P1 — 核心增强(让产品「能用起来」)
- 多标签页(一次只能开一个文件是当前最大效率瓶颈)
- 图片粘贴/拖拽(本地存到同目录,写技术文必备)
- Markdown 扩展:Mermaid 图、KaTeX 公式、TOC、脚注、任务列表勾选
- 全文搜索(有文件夹树却没有搜索,半残)

### P2 — 差异化(按定位二选一)
- 走 A:专注/打字机模式、字数与写作目标、双链 + 笔记库(向 Obsidian 靠)
- 走 B:多主题切换 + 自定义 CSS、「复制为富文本」(公众号/知乎)、导出 HTML/PDF/长图

## 如果只做三件事

1. **真代码高亮 + 统一渲染管线** — 修硬伤,投入小,观感立竿见影
2. **多标签页 + 最近文件** — 解决「打开即流失」,编辑器的及格线
3. **复制为富文本 / 导出 HTML** — 最小成本兑现「Markdown Nice」名字里的排版承诺,与纯写作工具拉开差异

## 下一步

建议从「真代码高亮」起手:同时修硬伤与技术债,理顺渲染管线,后续所有 Markdown 扩展均受益。
