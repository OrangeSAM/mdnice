# 产品演化评估 · 2026-07-07

> 一次产品经理视角的现状评估与演化建议快照,基于 v0.2.0 时点的代码现状。

## 产品初心

作者最初的痛点很朴素:在代码编辑器(VS Code 等)里看 Markdown 文件,字体、样式几乎没什么调整空间,阅读体验死板。于是想做一个「能调字体样式的 Markdown 查看器」,让自己看得舒服。

这条初心决定了产品的底色是**阅读器**——让 Markdown「看着 nice」——而非写作工具,也非排版输出工具。后者是后续可能附加的演化方向,但「阅读舒适、样式可调」才是立身之本;`preview_max_width`、`--strong-color`、默认浅色主题等设置项,都是为阅读体验而存在。

> 原话(2026-07-07):「我一开始想做这个产品,只是想让我更好地看 markdown 文件,因为在代码编辑器里面看,字体样式这些没啥调整空间。」

## 背景

Markdown Nice(Tauri v2 + Vue 3 本地 Markdown 编辑器)发展至 v0.2.0,核心能力:编辑(CodeMirror)、预览(markdown-it)、editor/split/preview 三视图、文件与文件夹管理、主题(默认浅色)、自动更新。本文对该节点做一次 PM 视角的盘点与规划。

## 现状速评

### 1. 预览的代码高亮是假的(硬伤)
`useMarkdown.ts` 里的 `hljs` 是 stub——`highlight()` 只做了 `escapeHtml`,无语法着色;`PreviewPanel.vue` 另 new 了一个没配 highlight 回调的 markdown-it。结果:预览代码块单色无高亮。对一个 Markdown 编辑器是观感硬伤。

### 2. 渲染逻辑重复且分裂
`useMarkdown` 与 `PreviewPanel` 各持一个 markdown-it 实例,配置不一致,`useMarkdown` 疑似闲置死代码。应统一为单一渲染管线。

### 3. 定位张力(最该先想清楚)
- 名字「Markdown Nice」(致敬 mdnice 排版)+ `preview_max_width`、`--strong-color` 等排版变量 → 暗示「主题排版 + 输出」
- welcome 文案「A quiet place to read and write Markdown」+ 现状功能 → 现状是「安静写作工具」(类 iA Writer / Typora)

两方向功能优先级几乎相反,需先定方向再排期。

## 竞品 Landscape

按定位分类(信息基于 2026-07 时点,定价/状态以官网为准):

### 1. 所见即所得 / 写作型(类 Typora)

| 产品 | 定位 | 模式 |
|---|---|---|
| Typora | 所见即所得标杆,编辑即渲染,极简 | 买断 ~$15 |
| iA Writer | 极致无干扰,强调「内容纯度」,多平台 | 买断 |
| MarkText | 开源版 Typora,所见即所得 | 免费开源(MIT) |
| Ulysses | Mac/iOS,图书馆式管理,适合长篇/博客发布 | 订阅 |
| Zettlr | 学术写作导向,集成 Zotero/Pandoc,引用管理 | 免费开源 |

### 2. 知识库 / 双链型

| 产品 | 定位 | 模式 |
|---|---|---|
| Obsidian | 本地 Markdown 知识库,双链 + 图谱 + 海量插件 | 个人免费,商用付费 |
| Logseq | 大纲式知识管理,本地优先,双链 | 免费开源 |
| Roam Research | 双链鼻祖,云端块引用 | 订阅(云端) |

### 3. 笔记型(Markdown 为主)

| 产品 | 定位 | 模式 |
|---|---|---|
| Bear | Mac/iOS,标签组织,颜值高,Markdown 导出 | 基础免费,Pro 订阅 |
| Notion | 块编辑器(非纯 MD),全功能 | 免费 + 订阅 |

### 4. 排版输出型(与「Markdown Nice」同源)

| 产品 | 定位 | 模式 |
|---|---|---|
| mdnice(网页版) | 主题排版,一键复制到公众号/知乎,本项目名字来源 | 免费 |
| Md2All | 在线 Markdown 排版,多主题 | 免费 |
| Markdown Here | 浏览器插件,富文本邮件/网页排版 | 免费开源 |

### 5. 开发者向

VS Code + Markdown 插件、MacDown(Mac 老牌分屏,开源)——功能向,体验偏工具。

### 对 mdnice 的启示

- **正面红海**:写作型(Typora/iA Writer)与知识库型(Obsidian)极成熟,正面硬刚无优势。
- **空白机会**:本地 + 排版输出 的组合几乎没有现成产品——mdnice 网页版要联网/登录、内容过它的服务器;本地版可主打「隐私 + 离线 + 一键复制排版」。这正是下文「A 为主、B 轻量输出层」的竞品依据:避开 Obsidian/Typora 腹地,占住「本地写作 + 漂亮输出」的夹缝。

## 战略选择

| 方向 | 核心 | 主战场 |
|---|---|---|
| A. 安静写作工具 | 编辑体验、专注、本地知识管理 | Typora / iA Writer / Obsidian |
| B. 排版输出工具 | 多主题、复制富文本、导出 | mdnice Web 版,卖点在本地+隐私 |

**推荐:A 为主,B 做轻量输出层。** 写作工具的留存靠日常打开;排版输出低频但高光。本地写作后顺手给「复制为公众号格式 / 导出」即可覆盖 B 的 80% 价值,不必做主题市场这类重运营的事。

## 路线图(按 ROI 分层)

### P0 — 基础体验(立即,几天内)
- 真·代码高亮(接 highlight.js 真包,统一渲染实例)— 修硬伤
- 最近文件列表(现在每次都要 Cmd+O 重新找,留不住人)
- 大纲导航(按 heading 自动生成,长文必备)

### P1 — 核心增强(让产品「能用起来」)
- 多标签页(一次只能开一个文件是当前最大效率瓶颈)
- 图片粘贴/拖拽(本地存到同目录,写技术文必备)
- Markdown 扩展:Mermaid 图、KaTeX 公式、TOC、脚注、任务列表勾选
- 全文搜索(有文件夹树却没有搜索,半残)

### P2 — 差异化(按定位二选一)
- 走 A:专注/打字机模式、字数与写作目标、双链 + 笔记库(向 Obsidian 靠)
- 走 B:多主题切换 + 自定义 CSS、「复制为富文本」(公众号/知乎)、导出 HTML/PDF/长图

## 如果只做三件事

1. **真代码高亮 + 统一渲染管线** — 修硬伤,投入小,观感立竿见影
2. **多标签页 + 最近文件** — 解决「打开即流失」,编辑器的及格线
3. **复制为富文本 / 导出 HTML** — 最小成本兑现「Markdown Nice」名字里的排版承诺,与纯写作工具拉开差异

## 下一步

建议从「真代码高亮」起手:同时修硬伤与技术债,理顺渲染管线,后续所有 Markdown 扩展均受益。
